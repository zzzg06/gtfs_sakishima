# 公開・デプロイ手順（ローカル + Cloudflare Tunnel）

関南乗換案内システムを、ローカルPCで本番起動し Cloudflare Tunnel で常設公開するための手順。
データ（`data/runtime/`）をファイル保存したまま公開できる方式。

## 前提・方針

- Next.js アプリをローカルで `npm run build` → `npm start`（本番モード・ポート3000）で常駐
- Cloudflare Tunnel で `https://maas.uclabo.net` に常設公開
- **必ず単一プロセスで運用**（メモリキャッシュ＋JSONファイル保存が1プロセス前提のため）
- `data/runtime/` は定期バックアップ（アップロード・車両・遅延・座標・検索履歴の保存先）

## 0. 環境変数（公開前に必須）

`.env.local`（Git管理外）に管理者認証を設定済み：

| 変数 | 用途 |
|---|---|
| `ADMIN_EMAIL` | 管理者メール（既定 admin@gtfs.local） |
| `ADMIN_PASSWORD` | 管理者パスワード（公開時は必ず固有の値に） |
| `SESSION_SECRET` | セッション署名鍵（自動生成済み・絶対に漏らさない） |

変更したら `npm start` を再起動。

## 1. 本番ビルド & 起動

```powershell
# 開発サーバー(npm run dev)が動いていないことを確認してから
npm run build
npm start
```

`http://localhost:3000` で本番モードが起動する。

> **注意**: `npm run dev` と `npm run build`/`npm start` を**同時に動かさない**こと。
> `.next` が壊れて `Cannot find module './XXX.js'` エラーになる。
> 壊れたら次の3手でリセット: `Remove-Item .next -Recurse -Force` → `npm run build` → `npm start`

## 2. cloudflared インストール

```powershell
winget install --id Cloudflare.cloudflared
```

## 3. トンネル作成（実施済みの記録）

```powershell
cloudflared tunnel login                          # ブラウザでドメイン(uclabo.net)を認可 → cert.pem
cloudflared tunnel create saki-shimaas            # トンネル作成
cloudflared tunnel route dns saki-shimaas maas.uclabo.net   # DNS(CNAME)作成
```

- トンネル名: `saki-shimaas`
- Tunnel ID: `0e7716c9-f715-4126-8d8f-63f64ede5273`
- 公開ホスト名: `maas.uclabo.net`
- 認証情報: `C:\Users\Triple-Zeta\.cloudflared\0e7716c9-f715-4126-8d8f-63f64ede5273.json`

## 4. 設定ファイル

`C:\Users\Triple-Zeta\.cloudflared\config.yml`:

```yaml
tunnel: saki-shimaas
credentials-file: C:\Users\Triple-Zeta\.cloudflared\0e7716c9-f715-4126-8d8f-63f64ede5273.json
ingress:
  - hostname: maas.uclabo.net
    service: http://localhost:3000
  - service: http_status:404
```

## 5. テスト起動

```powershell
# npm start が動いている状態で、別ウィンドウで
cloudflared tunnel ingress validate     # 設定検証（OKが出ればOK）
cloudflared tunnel run saki-shimaas
```

→ ブラウザで https://maas.uclabo.net が表示されれば成功。

## 6. 自動起動（PC再起動後も稼働）

### アプリ本体（PM2）

```powershell
npm install -g pm2
pm2 start "npm start" --name kannan
pm2 save
```

### トンネル（どちらか）

**方法1: タスクスケジューラ（推奨・簡単）**
- タスク スケジューラ →「タスクの作成」
- 全般:「最上位の特権で実行する」にチェック
- トリガー:「ログオン時」
- 操作: プログラム=`cloudflared.exe`、引数=`tunnel run saki-shimaas`

**方法2: Windowsサービス化**
サービスはSYSTEMアカウントで動くため、設定をSYSTEMプロファイルにコピーする：
```powershell
# 管理者PowerShell
$dst = "C:\Windows\System32\config\systemprofile\.cloudflared"
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item "$env:USERPROFILE\.cloudflared\*" $dst -Recurse -Force
cloudflared service install
Start-Service cloudflared
```

> テスト用の `cloudflared tunnel run`（手順5）は、自動起動を設定する前に Ctrl+C で止めること（2重起動エラー防止）。

## トラブルシュート

| 症状 | 対処 |
|---|---|
| `Cannot find module './XXX.js'` | `.next`破損。`Remove-Item .next -Recurse -Force` → 再ビルド |
| DNS `record already exists` | Cloudflareダッシュボードで既存`maas`レコードを削除して再実行 |
| トンネルは繋がるが502 | `npm start`が起動しているか、ポート3000か確認 |
| サービスが設定を読まない | SYSTEMプロファイルへ config.yml と認証jsonをコピー（手順6方法2） |
